# RTTTL（着メロ）

RTTTL は "Ring Tone Text Transfer Language" の略で、昔の携帯電話の着メロ形式です。
1 曲が**たった 1 行の文字列**になっていて、このパッケージはそれを Bluetooth MIDI で
送ります。だから[準備](./setup)で選んだチャンネルと音色の音が GarageBand から出ます。

曲は Web で探せます。`rtttl` と曲名で検索してみてください。

## 曲の書き方

```
 Ode : d=4,o=5,b=125 : 8e,8e,8f,8g,8g,8f,8e,8d,8c,8c,8d,8e,8e.,8d,4d
 ─┬─   ────────────   ────────────────────────────────────────────────
  │          │                        │
  │          │                        └─ 音符の並び（カンマ区切り）
  │          └─ 曲全体の既定値:
  │               d = 音符の長さ、o = オクターブ、b = 1 分あたりの拍数
  │               （書かれていないときは 4、6、63）
  └─ 曲の名前（まるごと省略できます）
```

音符は `長さ + 音名 + シャープ + オクターブ + 付点` で、音名以外は省略できます。

```
   8 c # 5 .
   │ │ │ │ └─ 付点は長さを 1.5 倍にする（8. は 8 分音符の 1.5 倍）
   │ │ │ └─── オクターブ（ヘッダの o= と違うときだけ書く）
   │ │ └───── # はシャープ
   │ └─────── 音名（a〜g。c と C は同じ音）
   └───────── 長さを全音符の分数で書く:
              1 = 全音符、4 = 4 分音符、8 = 8 分音符、16 = 16 分音符
```

小文字の `p` は休符です。

## 音の長さの決まり方

```
   b=125   （または「RTTTL のテンポを 125 BPM にする」）
        │
        └─ 全音符 = 240000 / 125 = 1920 ミリ秒

             4 分音符   4  = 1920 / 4   =  480 ミリ秒
             8 分音符   8  = 1920 / 8   =  240 ミリ秒
             付点 8 分  8. = 240 x 1.5  =  360 ミリ秒

   1 つの音符:  ├─────── 鳴っている ───────┤ ░ 15 ミリ秒 ░├─ 次の音符
                                              わずかな無音。これがないと
                                              同じ音が続いたときに
                                              1 つの長い音に聞こえます
```

**15 ミリ秒**より短い音はすべて 15 ミリ秒に伸ばします。それより速く送ると Bluetooth が
詰まるので、そもそも送らないようにしています。

## RTTTL を再生

曲を再生します。**このブロックは曲が終わるまで待ちます**。

```sig
let tune = "Ode:d=4,o=5,b=125:8e,8e,8f,8g,8g,8f,8e,8d,8c,8c,8d,8e,8e.,8d,4d"
gbpad.playRtttl(tune)
```

**パラメータ**

* **tune**: RTTTL の文字列

```blocks
gbpad.playRtttl("Ode:d=4,o=5,b=125:8e,8e,8f,8g,8g,8f,8e,8d,8c,8c,8d,8e,8e.,8d,4d")
```

待つブロックなので、「はじめに」か「ずっと」に置くのが自然です。**パッドから**
鳴らしたいときは、Control カテゴリの「背景で実行」で包んでください。包まないと、
曲が終わるまでパッドを見に行けなくなり、他のパッドが死にます。

```blocks
const TUNE = "Ode:d=4,o=5,b=125:8e,8e,8f,8g,8g,8f,8e,8d,8c,8c,8d,8e,8e.,8d,4d"
gbpad.onPadPressed(MidiPad.Logo, () => {
    control.inBackground(() => {
        gbpad.playRtttl(TUNE)
    })
})
```

## RTTTL のテンポを BPM にする

どの曲にも同じテンポ（1 分あたりの拍数）を強制します。

```sig
gbpad.setRtttlTempo(120)
```

**パラメータ**

* **bpm**: テンポ（0〜400。`0` は「上書きしない」で、曲に書かれたテンポのまま）

```blocks
gbpad.setRtttlTempo(90)
```

Web で拾ってきた曲はテンポがばらばらなので、このブロックがあると曲ごとに `b=` を
書き換えずに済みます。

| 設定 | どうなるか |
| --- | --- |
| `120` | どの曲も 120 BPM |
| `60` | 半分の速さ。教室でみんなが追いかけるとき |
| `240` | 2 倍の速さ |
| `0` | 上書きしない。曲に書かれたとおりに鳴る（このブロックを置かないのと同じ） |

設定は変えるまで残るので、「はじめに」に 1 回「RTTTL のテンポを 90 BPM にする」を
置けば、プログラム全体に効きます。

## RTTTL を停止

曲を途中で止めます。鳴っている音もその場で消えるので、音の長さの最後まで残りません。

```sig
gbpad.stopRtttl()
```

**パラメータ**

* なし

```blocks
gbpad.onPadPressed(MidiPad.A, () => {
    gbpad.stopRtttl()
})
```

## 同時に鳴る曲は 1 つだけ

2 つの曲が重なることはありません。新しい曲を始めると、鳴っていた曲はそこで止まります。
だから同じパッドを 2 回押すと、2 曲が重なるのではなく**曲が最初から鳴り直し**ます。
教室で交代しながらパッドを叩くときに、ちょうど都合のよい動きです。

```
   曲 A            ██ ██ ██ ██ ██
                             ╲
   もう一度パッドを押す ───────╲──────────────────────────────>
                               ╲  A は気づいて諦める
                                ╲ A が押さえていた音はその場で離す
   曲 B                        ██ ██ ██ ██ ██
```

「RTTTL を停止」と「すべての音を止める」も同じ仕組みを使うので、長い音の途中でも
すぐに止まります。

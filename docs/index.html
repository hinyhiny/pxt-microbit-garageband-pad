01システム構成

音は iPad 側で作ります。micro:bit が Bluetooth で送るのは「この音を鳴らせ / 止めろ」 という指示だけで、音声そのものは流れません。だからスピーカーもオーディオケーブルも 要りません。

BLE MIDI サービス

UUID 03B80E5A-EDE8-4B33-A751-6CE34EC4C700

広告名は BBC micro:bit [zapuv]

送るメッセージ

Note On / Note Off / Program Change / CC1 / CC7 / CC64 / Pitch Bend / All Notes Off

ポーリング周期

パッド 10 ms / 傾き 25 ms

「押している間だけ鳴る」を成立させるため、押下イベントではなくポーリングです

02パッドの仕様

パッドは 4 か所。押している間ずっと鳴り、離した瞬間に止まります。 ボタンの「クリック」ではなく、鍵盤を押さえている状態に近い動きです。

A+B は物理的に独立していません。 A と B を同時に押すと、A・B・A+B の 3 つが同時に 「押されている」状態になります。micro:bit にボタンが 2 つしかないためで、 打ち消す処理は意図的に入れていません。A+B を和音パッドに使うときは、 A と B の処理もそれを前提に設計してください。

05RTTTL の仕様

RTTTL（Ring Tone Text Transfer Language）は昔の携帯電話の着メロ形式です。 1 曲が 1 行の文字列で、そのまま Bluetooth MIDI で送られます。

文字列の構造

Ode : d=4,o=5,b=125 : 8e,8e,8f,8g,8g,8f,8e,8d,8c,8c,8d,8e,8e.,8d,4d

 名前          既定値                      音符の並び
（省略可）   d = 長さ / o = オクターブ      カンマ区切り
             b = 1 分あたりの拍数
             （書かれていなければ 4 / 6 / 63）
    8 c # 5 .
    │ │ │ │ └─ 付点: 長さを 1.5 倍にする
    │ │ │ └─── オクターブ（o= と同じなら省略）
    │ │ └───── # はシャープ
    │ └─────── 音名 a〜g（c と C は同じ）
    └───────── 長さ: 全音符の分数（4 = 4分、8 = 8分、16 = 16分）

  p = 休符

音の長さの計算

テンポの上書き

設定動き
120どの曲も 120 BPM で鳴る
60半分の速さ。教室で追いかけやすい
2402 倍の速さ
0上書きしない。曲に書かれたとおりに鳴る（既定）
400 超 / 負の値0〜400 に丸める
数値でない値無視して、直前の設定のまま

設定は変えるまで残るので、「はじめに」に 1 回置けばプログラム全体に効きます。 移調（キーの変更）は意図的に用意していません。曲の o= を書き換えてください。

06同時に鳴る曲は 1 つ

曲が重なることはありません。新しい曲が始まると、鳴っていた曲はそこで諦めます。 仕組みは「チケット」で、play RTTTL のたびに番号が進み、自分の番号が 変わっていたら次の音符で降りる、というだけです。

実装上いちばん壊れやすいのがここです。音を離す前に必ずチケットを照合しています。 照合しないと、奪われた側が「新しい曲の音」を消してしまいます。

ID の総数

5⁵ = 3125 通り30 台で衝突する確率は約 13%

「ペアリング不要」は必須です。 既定の JustWorks では MIDI のキャラクタリスティックに 「読み取りに認証が必要」が付き、iPad が接続直後に読もうとして ATT Insufficient Authentication を受け、iOS が即座に切断します。設定は .hex に焼き込まれるので、 変更後は必ず焼き直してください。焼き直さないと ID の [ ] も戻りません。

ID はチップのシリアル番号から作られるため変更できません。書き込み直しても残ります。 同じ ID が 2 つ見えたときは、片方につないで本体を見てください。接続時に ✓ が出るのは 自分の本体なので、違えば切断してもう片方につなぎます。

意図的にそうしていること

こと理由
A+B の打ち消しがないmicro:bit のボタンは 2 つだけ。同時押しを「3 つ目のパッド」として使えるようにしている
play RTTTL が待つ内部で勝手に「背景で実行」を呼ばない。必要なら利用者が包む（そうしないと意図せず曲が重なる）
移調がないテンポと同じ軸に機能を増やさない。キーは曲の o= で変える
RTTTL は 1 文字ずつ解析部分文字列を作らない。micro:bit はメモリがすぐ足りなくなる
音符の間の 15 ms の無音同じ高さの音が続いたときに 2 つの音に聞こえるようにするため
